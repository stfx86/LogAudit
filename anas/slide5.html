Étape 5 : Exfiltration des Données

PARTIE 1 : ARCHIVAGE ET COMPRESSION

ID: WAZUH-SEC-05A
[EVIDENCE 1] DÉTECTION D'ARCHIVAGE (TAR) MITRE ATT&CK: T1560
OSsec détecte l'exécution de la commande /usr/bin/tar le 8 Mai à 21:45:55. Les logs d'audit système confirment les arguments passés : tar -czf /home/stt/everything.tar.gz, montrant la création de l'archive dans le répertoire de l'utilisateur.
[EVIDENCE 2] PROCESSUS DE COMPRESSION (GZIP) MITRE ATT&CK: T1560.001
Suite à la commande précédente, OSsec enregistre l'exécution de /usr/bin/gzip. L'appel système (SYSCALL execve) montre le processus gzip s'exécutant dans le répertoire /home/stt.
[EVIDENCE 3] PRÉPARATION À L'EXFILTRATION (ENV) MITRE ATT&CK: T1048
Moins d'une minute plus tard, à 21:46:45, une nouvelle alerte OSsec est générée pour l'exécution de /usr/bin/env, indiquant la préparation d'un environnement (potentiellement pour le transfert des données compressées).

Étape 6 : Exfiltration via SFTP

(NOUVELLE SESSION SSH)

ID: WAZUH-SEC-06
[EVIDENCE] EXFILTRATION SUR CANAL CHIFFRÉ (SFTP) MITRE ATT&CK: T1048.002
Les logs d'authentification enregistrent un cycle complet de connexion : l'ouverture d'une session SSH, l'appel au sous-système sftp-server pour transférer l'archive précédemment créée, suivi de la fermeture immédiate de la session SSH.

Étape 7 : Exploration Post-Exfiltration

ET VOL DE CREDENTIALS

ID: WAZUH-SEC-07
[EVIDENCE] DÉTECTION D'EXPLORATION (CAT) MITRE ATT&CK: T1083
OSsec détecte l'exécution de la commande /usr/bin/cat. Cette commande est typiquement utilisée en phase de post-compromission pour explorer manuellement le contenu de fichiers locaux sur la machine cible.
[EVIDENCE] INSPECTION DE CODE SOURCE (VIM) MITRE ATT&CK: T1083
Peu après, l'exécution de l'éditeur /usr/bin/vim est enregistrée. L'attaquant ouvre le fichier source app.py pour inspecter la logique de l'application et chercher des informations sensibles.
[EVIDENCE] DÉCOUVERTE D'IDENTIFIANTS EN DUR MITRE ATT&CK: T1552.001
L'inspection de app.py expose des identifiants MySQL codés en dur (utilisateur root / mot de passe password123). Ces credentials permettent à l'attaquant d'accéder directement à la base de données applicative.

Étape 8 : Exfiltration de la Base de Données

VIA MYSQLDUMP

ID: WAZUH-SEC-08
[EVIDENCE] EXÉCUTION DE MYSQLDUMP MITRE ATT&CK: T1567
OSsec enregistre l'utilisation de l'utilitaire /usr/bin/mysqldump le 8 Mai à 21:50:33. L'attaquant commence l'extraction de la base de données zipvault en utilisant les privilèges root obtenus précédemment.
[EVIDENCE] UTILISATION DES CREDENTIALS VOLÉS (EXECVE) MITRE ATT&CK: T1552.001
Le log détaillé de l'appel système révèle les arguments en clair : -u root -p password123. L'attaquant réutilise avec succès le mot de passe extrait du fichier app.py pour dumper l'intégralité de la base de données.
[EVIDENCE] VÉRIFICATION DU DUMP SQL MITRE ATT&CK: T1083
Une commande /usr/bin/cat est enregistrée à 21:51:19. L'attaquant vérifie le contenu du fichier SQL généré pour s'assurer que l'extraction des données sensibles s'est déroulée correctement avant l'exfiltration finale.

Étape 9 : Tentative d’Élévation de Privilèges

ANALYSE DES TENTATIVES D'ESCALADE

ID: WAZUH-SEC-09
[EVIDENCE] TENTATIVE 1 : TÉLÉCHARGEMENT D'EXPLOIT (CURL) MITRE ATT&CK: T1105
L'attaquant tente de télécharger un exploit public depuis copy.fail/exp en utilisant curl. Les arguments révèlent l'URL de destination.
[EVIDENCE] TENTATIVE 2 : ÉCHEC DE CHANGEMENT D'UTILISATEUR (SU) MITRE ATT&CK: T1110
Tentative de basculement vers un compte privilégié via su. Wazuh enregistre un échec d'authentification PAM (Password failed).
[EVIDENCE] TENTATIVE 3 : RECONNAISSANCE DU NOYAU (UNAME) MITRE ATT&CK: T1082
Exécution de uname -r pour identifier la version précise du noyau Linux afin de rechercher des exploits de type "Local Privilege Escalation".
[EVIDENCE] TENTATIVE 4 : RECHERCHE DE BINAIRES SUID (FIND) MITRE ATT&CK: T1548.001
L'attaquant utilise find pour lister les fichiers avec le bit SUID activé, cherchant des binaires mal configurés pour élever ses privilèges.
[EVIDENCE] TENTATIVE 5 : CONFIGURATION SUDO VULNÉRABLE MITRE ATT&CK: T1548.003
La commande sudo -l révèle une faille critique : l'utilisateur dispose des droits NOPASSWD: ALL, permettant d'exécuter n'importe quelle commande en root.
[EVIDENCE] ÉLÉVATION DE PRIVILÈGES RÉUSSIE (SUDO -I) SITUATION : ACCÈS ROOT TOTAL
L'attaquant exécute sudo -i. Le log d'audit confirme l'élévation réussie avec un EUID=0 (root) et l'ouverture d'une session shell privilégiée.
